SeoulWalk AI Agent Architecture

오픈클로(OpenClaw)의 마이크로서비스 오케스트레이션과 헤르메스(Hermes)의 자율 3계층 메모리 아키텍처를 결합한 차세대 산책 추천 에이전트 설계안입니다.

OpenClaw Style

API Gateway & Orchestrator

적용 범위: seoul-walk-platform (Backend)의 중앙 라우팅 엔진

SeoulWalkApp(React Native)에서 발생하는 이벤트를 실시간으로 수신하고, 복잡한 외부 서비스를 매끄럽게 연결하는 마이크로서비스 컨트롤 타워 역할을 수행합니다.

핵심 구현 방안

  • 이벤트 라우팅: 사용자의 '산책 시작', '경로 이탈', '날씨 조회' 이벤트를 Trigger로 받아 적절한 모듈로 분배합니다.
  • Tool Orchestration: Mapbox Directions API, 기상청 날씨 API 등 독립된 외부 서비스를 하나의 에이전틱 파이프라인으로 묶어 실행합니다.
  • Stateless Fast API: 사용자 요청에 즉각 반응하기 위해 상태를 가지지 않는 가벼운 API 게이트웨이 패턴을 app.py에 적용합니다.
Hermes Style

Autonomous Loop & 3-Tier Memory

적용 범위: Geo-AI Profile Engine & Background Daemon

사용자가 앱을 끄더라도 백그라운드에서 자율 루프를 돌며 사용자의 "Taste Drift(취향 변화)"를 학습하고 3계층 메모리를 업데이트하는 지능형 워커입니다.

핵심 구현 방안

  • Background Daemon: Celery 또는 Asyncio 기반으로 정해진 주기에 맞춰 사용자의 미완료 산책 피드백을 분석하고 모델을 조정합니다.
  • 3-Tier 하이브리드 메모리:
    - Working: 현재 산책 중인 세션 데이터 (Redis)
    - Episodic: 과거 산책 기록과 달성률 로그 (PostgreSQL JSONB)
    - Semantic: 사용자 취향과 불변 선호도 정보를 벡터화 (ChromaDB/PGVector)
  • 스킬(Skill) 자동 생성: 고비용의 LLM 추론이 성공적인 산책 경로를 도출하면, 이를 '캐싱된 스킬 레시피'로 저장하여 이후 유사 요청 시 재사용합니다 (비용/속도 최적화).

Unified Master Blueprint: 1-Server Agentic Lifecycle

Product & UX Strategy FAQ

📦 Q1. 이 플랫폼을 위해 총 몇 개의 Git 레포지토리(Repo)가 필요한가요?

마이크로서비스 아키텍처 특성상 최소 3개, 권장 4개의 레포지토리 분리를 권장합니다.

① Frontend Repo: React Native 기반 모바일 앱 (SeoulWalkApp)
② API Gateway & Agent Repo: Python(FastAPI) 기반 메인 오케스트레이터 및 LLM 프롬프트/라우팅 로직
③ Background Worker Repo: Python/Celery 기반의 새벽 취향 압축 자율 데몬 (Gateway와 분리 권장)
④ Presence Server Repo: Node.js 기반 실시간 웹소켓 서버 (GPS 및 상태 추적 전용)

🗺️ Q2. 포켓몬고 스타일의 3D 근방 메인 뷰 + 하단 전체 스냅샷 UX는 괜찮은가요?

매우 훌륭하고 이상적인 접근입니다. 산책 앱의 본질은 목적지 도달이 아니라 '지금 내가 걷고 있는 주변의 공간적 몰입감'입니다. Mapbox의 3D Terrain 및 Building 레이어를 활용해 1인칭 뷰(Pitch ~60도)로 근방을 보여주면 보행자에게 강한 현장감을 줍니다. 동시에 하단 미니맵(전체 스냅샷)으로 전체 남은 거리와 이탈 여부를 확인하게 하면 길 잃을 불안감을 완벽히 해소할 수 있습니다.

⏱️ Q3. 에이전트 생성에 30초 이상 걸릴 경우, 유저의 흥미를 어떻게 유지하나요?

다중 에이전트 라우팅은 외부 API 여러 개를 호출하므로 지연(Latency)이 불가피합니다. 이를 해결하기 위한 두 가지 장치가 필요합니다.

1. 사고 과정의 시각화 (Streaming UI): 단순한 로딩 스피너 대신, 에이전트가 무슨 생각을 하는지 실시간 텍스트로 노출합니다. (예: "현재 위치 미세먼지 확인 중..." ➔ "그늘 많은 공원 탐색 중..." ➔ "날씨 고려해 경로 최적화 중...")
2. 캐시 퍼스트 (Skill Caching): 백그라운드 워커가 미리 유저 근처의 좋은 산책로 템플릿(Skill)을 구워둡니다. 요청 시 1~2초 만에 캐시된 기본 경로를 먼저 띄워주고, 백그라운드에서 추가 최적화를 거쳐 부드럽게 경로를 업데이트(Patch)합니다.

🌿 Q4. "자연을 보러 와서 폰만 보게 되지 않나?" 이 모순을 어떻게 극복하나요?

앱의 최종 가치는 역설적이게도 'Screen-free (화면을 보지 않는) 경험'에 있어야 합니다. 폰을 끄고도 자연을 즐길 수 있도록 다음 기능이 필요합니다.

1. 햅틱 및 오디오 네비게이션: 교차로, 뷰 포인트 등에 도달했을 때 스마트폰 진동 패턴이나 부드러운 오디오(예: "오른쪽 벚꽃길로 진입합니다")로 화면을 보지 않고도 안내합니다.
2. 관대한 이탈 감지 (주머니 속 수호천사): 유저가 의도적으로 샛길로 빠져 자연을 탐험할 때 시끄럽게 경고하지 않고 '탐험 모드'로 인지해 침묵합니다. 진짜 막다른 길일 때만 개입합니다.
3. 산책 후의 회고 (Episodic Report): 산책 중에는 앱의 존재감을 지우고, 종료 후 걸었던 궤적, 심박수, 머물렀던 스팟 등을 엮어 아름다운 '산책 리포트'를 생성해주면 앱의 리텐션이 크게 상승합니다.
