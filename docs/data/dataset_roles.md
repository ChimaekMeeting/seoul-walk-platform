# V1 데이터 역할과 적재 상태

## 1. 명칭 원칙

`Node`와 `Edge`는 실제 도보 경로 그래프에만 사용한다.

```text
서울시 도보 네트워크 NODE → WalkNode
서울시 도보 네트워크 LINK → WalkEdge → NetworkX edge
```

지도상의 Point라고 해서 WalkNode가 되는 것은 아니다. 랜드마크·화장실·CCTV·버스정류장 등은 POI 또는 Layer의 Point로 관리한다.

| 명칭 | 의미 |
|---|---|
| `WalkNode` | 실제 도보망의 교차·분기·시작·종료 지점 |
| `WalkEdge` / `LINK` | 두 WalkNode를 연결하는 실제 보행 구간 |
| `POI` / Point Layer | 경로 주변 시설이나 장소 |
| Line Layer | 기존 WalkEdge의 속성 검증·보강에 사용하는 선형 자료 |
| Polygon Layer | 공원 등 영역 기반 점수·검증 자료 |
| Score Source | WalkEdge의 숫자 점수를 만드는 원본 또는 Layer |

## 2. 처리 단계

같은 “적재”라는 말로 네 단계를 섞지 않는다.

| 단계 | 의미 |
|---|---|
| RAW 적재 | 원본을 `*_raw` 테이블 또는 로컬 원본으로 보존 |
| Layer 변환 | 원본을 안전·자연·랜드마크 등 서비스 목적별 테이블로 정리 |
| Graph 반영 | 실제 WalkNode·WalkEdge 생성 또는 기존 WalkEdge 속성 보강 |
| Score 반영 | Layer를 `safety_score`, `nature_score` 등 WalkEdge 숫자 필드로 집계 |

## 3. 상태값 분리

코드 연결과 V1 승인을 하나의 `active` 상태로 합치지 않는다.

| 구분 | 상태 | 의미 |
|---|---|---|
| 코드 | `wired` | RAW부터 Graph 또는 Layer·Score까지 실행 코드가 연결됨 |
| 코드 | `partial` | RAW 로더 등 일부 코드만 연결됨 |
| 코드 | `unwired` | 실행 코드에 연결되지 않음 |
| 검토 제안 | 사용 | 기존 분석상 V1 입력으로 사용할 수 있다고 판단 |
| 검토 제안 | 제한 사용 | 용도·지역·프로필을 제한해야 함 |
| 검토 제안 | 보류 | 품질·범위·정책 문제가 해결되기 전 사용하지 않음 |
| 검토 제안 | 참고 | 조사·검증 자료로만 사용 |
| 채원 승인 | `승인` | 채원이 V1 사용을 최종 결정함 |
| 채원 승인 | `제한 사용` | 지정된 용도·속성에만 사용하고 다른 판정으로 확대하지 않음 |
| 채원 승인 | `미결정` | 채원이 아직 사용 여부를 결정하지 않음 |
| 채원 승인 | `서비스 미사용` | 검증 근거로만 보존하고 V1 서비스 DB에는 반영하지 않기로 결정함 |
| 채원 승인 | `보류` | 품질·범위 문제가 해결되기 전 V1에 반영하지 않기로 결정함 |
| 제거 | `removed` | 중복 또는 V1 미사용으로 로컬 RAW에서 제거 |

현재 개발 DB에 실제 적재됐다는 뜻은 아니다. DB 상태는 `확인`, `미확인`, `미적재`로 별도 기록한다.

## 4. 기본 도보 그래프

| 데이터 | 역할 | 결과 | 코드 상태 | 채원 승인 | DB 상태 |
|---|---|---|---|---|---|
| 서울시 자치구별 도보 네트워크 공간정보 | V1 유일 기본 그래프 | `walk_nodes`, `walk_edges` | `wired` | `승인` | 미확인 |

V1에서는 다른 RAW의 Point나 LineString을 즉시 WalkNode·WalkEdge로 만들지 않는다. 기존 도보망에 없는 실제 보행 구간임이 확인되고 연결 지점까지 검증된 경우에만 그래프 보강 후보가 된다.

## 6. 기존 WalkEdge 속성 보강 후보

| 원본 | 예상 역할 | Graph 처리 | 상태 |
|---|---|---|---|
| 서울시 대로변 횡단보도 위치정보 | 횡단보도 플래그 검증 | 기존 WalkEdge의 원본 플래그와 비교 | `validation-only` |
| 서울시 육교 공간정보 | 육교 플래그 검증 | 기존 WalkEdge의 원본 플래그와 비교 | `validation-only` |
| 전국도로터널정보표준데이터 | 터널 플래그 검증 | 기존 WalkEdge의 터널 속성과 비교 | `approved-pending` |
| 서울시 자동차 전용도로 위치정보 | V1 서비스 입력에서 제외 | 좌표계와 선형 geometry를 복원할 수 없어 기존 WalkEdge의 통행 가능 속성을 우선 사용 | `excluded` |

이 데이터들은 검증 전에는 새 WalkNode·WalkEdge를 만들지 않는다.

POI를 목적지와 연결해야 하면 POI 자체를 WalkNode로 만들지 않고, 가장 가까운 기존 WalkNode 또는 WalkEdge를 참조한다.

## 10. 데이터별 완료 조건

각 데이터는 아래 항목이 모두 결정되어야 V1 데이터 작업이 완료된다.

1. V1에서 사용하는가
2. RAW 적재가 필요한가
3. POI·Line·Polygon·Score Source 중 무엇인가
4. 생성할 Layer가 무엇인가
5. 보강할 WalkEdge 필드 또는 score가 무엇인가
6. 공간 매핑과 품질 검증 기준이 무엇인가
7. 코드에서 실제로 실행되고 있는가
8. 개발 DB의 실제 적재 건수를 확인했는가

- 공원 Polygon 중 서울 경계 밖 geometry는 원본에는 남기되 서울 WalkEdge의 교차·Score 계산에서는 제외한다.
- 실제 Line geometry가 없는 둘레길·문화길 좌표점은 선형 경로처럼 연결하지 않는다.

### 11.4 도보망 연결 계약 확정

확인 기준은 2026-07-30 로컬 원본과 WalkEdge 279,016개이다. Point는 WalkEdge까지 20m·50m·100m 근접률과 현재 H3 resolution 9 셀 연결률을 확인했다. Line은 피처 하나가 한 번이라도 근접하는 비율과 20m 간격 표본으로 측정한 전체 선형 연결률을 분리했다. Polygon은 실제 교차와 Edge 내부 길이 비율을 사용했다.

`도보망 연결`은 모든 원본을 WalkNode로 바꾸는 일이 아니다. 사용자 요청에서 사용할 수 있도록 각 원본을 H3 기반 Score, WalkEdge Tag, WalkNode·WalkEdge 연결 POI, Polygon 교차 속성 또는 참고 전용 자료 중 하나로 변환하는 일이다.

연결 방식별 공통 계약은 다음과 같다.

- H3는 주변 시설 밀도를 Score로 전달하는 중간 격자이며 실제 도로 연결선이 아니다.
- H3 기반 Score와 정확한 Edge Tag를 구분한다. `school_zone`, `tunnel`, `pedestrian_priority` 같은 Tag는 별도 공간 검증 후 Edge에 저장한다.
- 편의·접근성 Point는 최대 50m 안에서만 WalkNode·WalkEdge에 연결한다. 한도를 넘으면 다른 도로에 강제 연결하지 않고 표시 전용으로 남긴다.
- Line은 한 지점의 근접 여부만으로 전체 Line을 연결하지 않는다. 전체 길이 근접률, 도로명, Edge 연속성을 함께 확인한다.
- Polygon은 중심점 근접이 아니라 실제 Edge 교차 길이를 사용한다.
- `blocked_tags`는 원본 Point나 H3 셀에 적용하지 않고 검증을 마친 WalkEdge Tag에만 적용한다.
- 프로필과 `Weights`는 확정된 Score의 중요도를 조절하며, 데이터가 없는 구를 불리하게 만드는 용도로 사용하지 않는다.

사용자 요청에서의 처리 순서는 다음과 같다.

1. 출발점 주변 WalkNode와 WalkEdge를 그래프로 불러온다.
2. 프로필과 `Weights`로 Edge의 안전·자연·편의 등 Score 비용을 계산한다.
3. 사용자가 피하도록 선택한 `blocked_tags`가 있는 Edge를 제외하거나 강하게 감점한다.
4. 남은 Edge의 비용을 기준으로 경로를 생성한다.
5. 경로 주변에 연결된 화장실·교통·접근성 POI를 응답에 포함한다.

### 11.5 결측·편향 처리 계약 확정

결측은 실제 시설의 부재와 동일하게 해석하지 않는다. 원본 행과 원본 값은 보존하고, 정제값·제외 사유·공간 사용 여부를 구분한다. 근거가 확인된 오류만 보정하며 결측 숫자를 `0`, 결측 좌표를 `(0, 0)`으로 대체하지 않는다.

처리 상태의 의미는 다음과 같다.

| 처리 상태 | 의미 |
|---|---|
| 정상 사용 | 현재 확인된 결측·편향이 서비스 역할을 훼손하지 않음 |
| 보정 후 사용 | 주소·시설 식별값·공식 위치처럼 재현 가능한 근거로 오류를 수정한 항목만 사용 |
| 제한 사용 | 제공된 위치에는 가점·속성을 적용하지만 미제공 지역을 감점하거나 열악하다고 판단하지 않음 |

| 20 | 서울시 지하철 출입구 리프트 | 지역 편향·제한 사용 | 제공된 15개 구의 83개 시설만 접근성 POI 후보로 사용한다. 미제공 구를 접근 불가로 판단하거나 감점하지 않는다. |
| 21 | 서울시 지하철역 엘리베이터 | 제한 사용 | 552개 시설을 접근성 POI로 사용하되 시설 개수를 구 전체 접근성 점수로 직접 환산하지 않는다. |
| 22 | 서울시 버스정류소 | 경계 보정 후 사용 | 경계 내부 11,237개는 포함 자치구를 사용하고 접경 16개는 최근접 자치구와 거리를 함께 기록한다. 자치구 보정과 실제 POI-Edge 연결을 구분하며, 50m 밖 Point를 다른 Edge에 강제 연결하지 않는다. |
| 23 | 서울시 공중화장실 위치 | 보정 후 사용 | 잘못된 대전 좌표 2건은 확인된 서울 좌표로 교체하고 `구 명칭` 공백 15건은 주소로 보완한다. 50m 이내 Point만 POI-Edge 관계를 만들고 초과 Point는 표시 전용으로 남긴다. |
| 24 | 공중화장실 상세정보 | 위치 결측·속성 전용 | 좌표가 없으므로 23번 위치 원본과 명칭·주소가 결합되는 운영 속성만 사용한다. 결합되지 않은 행은 임의 좌표를 만들지 않고 별도 geocoding 검토 대상으로 둔다. |
| 25 | 서울 상권 | 중복·밀도 편향·제한 사용 | 537,489행을 개별 가점하지 않고 약 162,864개 위치와 업종을 H3 셀별로 집계한다. 셀별 최대 가점을 적용하고 상권이 적은 지역을 위험하거나 불편하다고 단정하지 않는다. |

공통 처리 계약은 다음과 같다.

- 원본값과 정제값을 분리하고 보정 근거와 제외 사유를 재현 가능하게 기록한다.
- 결측 숫자를 `0`, 결측 좌표를 `(0, 0)`으로 대체하지 않는다. 의미가 확인되지 않은 숫자 `0`도 실제 없음으로 단정하지 않는다.
- 동일 위치의 반복 행은 서비스 역할에 맞게 집계하되, 좌표만 같은 서로 다른 시설은 자동 병합하지 않는다.
- 일부 구에만 제공된 데이터는 존재가 확인된 위치의 제한 가점에만 사용하고 미제공 지역에는 감점을 주지 않는다.
- 구별 비교가 필요하면 단순 건수가 아니라 구 면적, WalkEdge 길이 또는 H3 셀 단위로 정규화하고 최대 가점을 둔다.
- 연결 거리 밖 Point, 불완전한 Line, 서울 경계 밖 geometry를 다른 도로·자치구에 강제로 맞추지 않는다.
- 데이터 날짜·버전이 다른 원본은 최신이라고 추정해 덮어쓰지 않고 출처와 기준일을 함께 보존한다.

### 11.6 최종 서비스 역할과 상태 확정

최종 역할은 하나의 데이터가 DB와 경로 요청 사이에서 무엇을 만드는지를 뜻한다.

| 역할 | 최종 출력 | 알고리즘 사용 |

| 기본 경로망 | `WalkNode`, `WalkEdge` | 경로 탐색 그래프 |
| Score Source | 정규화된 Edge Score | `Weights`와 프로필로 Edge 비용 보정 |
| Edge Tag Source | 검증된 `WalkEdge` Tag | 프로필별 가감점 또는 사용자 `blocked_tags` |

| 메타데이터 | 명칭·설명·운영정보 | POI·경로 설명 보강, 독립 Score 금지 |
| 검증 전용 | 비교·품질 확인 결과 | 런타임 그래프에 적재하지 않음 |
| 보류·제외 | 원본과 보류·제외 근거 | 경로 계산에 사용하지 않음 |

알고리즘 입력 계약은 다음과 같이 확정한다.

- 기존 `Weights`의 `safety`, `nature`, `slope`, `running`, `landmark`, `child` 중 `child`는 어린이보호구역을 안전 가점으로 선호하지 않도록 의미와 공식을 수정한다. 어린이보호구역은 `vehicle_caution` Edge의 주의·감점 근거이다.
- 편의시설과 상권을 경로 선호에 반영하려면 `Weights`와 프로필에 `convenience` 입력을 추가한다.
- 엘리베이터·리프트를 접근성 경로 후보에 반영하려면 `accessibility` 입력을 추가한다. 시설 존재만으로 전체 경로의 무장애 접근성을 보장하지 않는다.
- `park_overlap_ratio`를 `GraphRepository`가 NetworkX Edge에 전달하고 자연 비용 계산에서 `raw_is_park_green`과 별도 근거로 사용한다.
- `blocked_tags`는 검증된 Edge Tag에만 적용한다. 터널은 기본 차단하지 않고 쾌적도 감점으로 처리한다.
- 현재 프로필의 `blocked_tags=["underground"]`와 실제 생성 Tag인 `subway_network`, `building_inside`, `tunnel`의 의미가 일치하지 않는다. 임의 합성 없이 차단하려는 실제 대상을 결정한 뒤 프로필과 테스트를 함께 수정한다.
- POI는 Score만 저장하지 않고 경로 응답에서 시설명·거리·종류를 제공할 수 있도록 WalkNode·WalkEdge 연결 관계를 보존한다.
- DB 재적재 후 실행 중인 서버의 메모리 Graph는 자동 갱신되지 않으므로 서버를 재시작한다.

### 11.7 25개 기준 최종 요약

| 최종 상태 | 데이터셋 수 |
|---|---:|
| `V1 활성` | 1 |
| `V1 적재 활성·알고리즘 미연결` | 1 |
| `일부 구현·V1 비활성` | 3 |
| 연동 승인·구현 대기 계열 | 11 |
| `검증 전용` | 4 |
| `보류` | 4 |
| `제외` | 1 |

25개 데이터의 서비스 역할과 품질 정책은 확정되었다. 현재 배포 가능한 V1 기본 그래프는 도보 네트워크이며 공원 Polygon의 `park_overlap_ratio`는 적재되지만 아직 경로 비용에 소비되지 않는다. 안전·어린이 Score는 `legacy-all` 구현만 있고 기본 V1에서는 실행되지 않는다. 편의·접근성 POI, 가로수길·보행자우선도로 Tag, 상권 Score는 계약만 확정됐으며 구현과 재적재가 남아 있다.
